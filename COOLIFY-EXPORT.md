# Экспорт демо-магазина в Coolify

Эта инструкция описывает отдельный Coolify-образ витрины, собранный из текущего проекта. Сборка сохраняет каталог, фотографии, корзину в браузере, консультанта с демонстрационными ответами и админку для управления каталогом. Оформление заказов, индивидуальные заявки и отправка свободного текста консультанту отключены в Docker-сборке; такие данные не отправляются приложению и не записываются в D1. Рабочий сайт в Sites этот режим не включает.

## Что понадобится

- европейский VPS с установленным Coolify, публичным IPv4 и открытыми входящими TCP-портами 80 и 443;
- приватный Git-репозиторий, доступный Coolify (например, GitHub, GitLab или собственный Git-сервер);
- поддомен для показа, например `demo.lider-massiv.ru`.

## 1. Создать приватный Git-репозиторий

GitHub заранее не обязателен для подготовки проекта, но Git-источник нужен Coolify для сборки и повторных развёртываний. Создайте приватный пустой репозиторий и перенесите туда эту версию проекта. Не публикуйте `.env`, `.dev.vars`, ключи ИИ, пароли или данные рабочей базы.

В Coolify подключите GitHub App либо добавьте отдельный read-only deploy key к одному репозиторию. Не используйте пароль от GitHub или ключ, который даёт Coolify право записывать в репозиторий.

## 2. Подготовить DNS для демо

В DNS-зоне домена у регистратора создайте запись:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `demo` | публичный IPv4-адрес европейского VPS |

Не меняйте записи `@` и `www`: они относятся к основному домену. Дождитесь, пока `demo.lider-massiv.ru` начнёт разрешаться в IPv4 VPS.

## 3. Создать приложение Coolify

1. Откройте нужные Project и Environment и нажмите **New Resource**.
2. Выберите приватный Git-репозиторий и ветку с этим проектом.
3. В качестве Build Pack выберите **Dockerfile**; путь к Dockerfile — `Dockerfile` в корне репозитория.
4. Укажите внутренний порт `8787`.
5. В Domains добавьте `https://demo.lider-massiv.ru`.
6. Демо-сборка уже выдаёт `noindex` в HTML и HTTP-заголовке; дополнительно включите **Noindex** для демо-домена в Coolify, если эта настройка есть в вашей версии.
7. Добавьте постоянное хранилище, смонтированное в контейнер по пути `/data`.

Coolify использует каталог `/data` для локального состояния D1. Не удаляйте и не заменяйте это хранилище при обычном redeploy, иначе будут удалены сохранённые изменения каталога и сессии админки.

## 4. Настроить доступ к админке

На своём компьютере в корне проекта запустите:

```text
node scripts/generate-admin-credentials.mjs
```

Скрипт один раз напечатает случайный пароль и его PBKDF2-хеш. Сохраните пароль в менеджере паролей, а в Coolify → Configuration → Environment Variables добавьте:

```text
ADMIN_LOGIN=ваш-email
ADMIN_PASSWORD_HASH=100000:<salt>:<hash>
```

В `ADMIN_PASSWORD_HASH` вставьте напечатанное скриптом значение целиком, включая `100000:`. Сам пароль в Coolify не добавляйте. Для обеих переменных включите **Runtime Variable** и отключите **Build Variable**: приложение читает их только после запуска. Значение Build Variable может попасть в журнал сборки и метаданные Docker-образа. После изменения переменных выполните новую сборку и Deploy, а не только Restart. Админка доступна по адресу `https://demo.lider-massiv.ru/admin`.

## 5. Развернуть и проверить

Нажмите Deploy и дождитесь успешного завершения сборки. Затем проверьте:

- главную страницу, каталог и фотографии товаров;
- карточку товара и локальную корзину — её содержимое хранится только в браузере;
- `/admin`: вход, категории, поиск, редактирование товара, цены, скидки и наличие;
- что оформление заказа и заявка на индивидуальный расчёт в демо отключены;
- что ответы демонстрационного консультанта формируются в браузере и не передают текст посетителя серверу;
- что домен открывается по HTTPS и корректно работает на телефоне.

У Coolify прокси должен принимать запросы на портах 80 и 443. Для демо-домена Noindex лишь просит поисковики не индексировать страницу и не ограничивает доступ к ней; если сайт должен видеть только заказчик, отдельно поставьте парольную защиту на уровне прокси.

## Важно о назначении этой сборки

Этот образ предназначен для демонстрации. Он запускает приложение в локальной Cloudflare-совместимой среде Wrangler, хранит служебное состояние и изменённый каталог в постоянном томе VPS и не подключается к Cloudflare D1/R2. Включать сбор этой сборкой реальных заказов и контактов покупателей нельзя. Для рабочего магазина следует отдельно перенести backend на поддерживаемый production-стек (например, Node.js + PostgreSQL), настроить резервное копирование, доступы и обработку заказов на российском сервере.

При запуске основного домена уберите демо-режим `VITE_DEMO_MODE`, замените `demo.lider-massiv.ru` в метаданных на рабочий домен, проверьте канонические адреса и только затем добавьте полноценный `sitemap.xml` и включите индексацию. Демо-сайт намеренно не публикует карту сайта.
